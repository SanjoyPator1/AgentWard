# AgentWard
AgentWard: an AI agent harness for synthetic patients. Synthea-generated FHIR behind an MCP tool layer, with code-oracle graded evals for clinical-ops agent tasks. Synthetic data only - research use, not for clinical use.

## What this repo is

A hospital ward staffed by agents is the metaphor: a ward is a set of patients
competing for a limited amount of attention, and that's what every feature here
is really about. The substrate is a HAPI FHIR server loaded with Synthea's
synthetic patients, reached through our own MCP tool layer. Every feature is
graded by a code oracle written against the same underlying data, not by an
LLM judging its own homework.

All data is synthetic, generated by Synthea. No real patient data goes in this
repo, ever. Nothing this project produces is clinical advice or validated for
clinical use.

## Repo layout

```
docs/          real documentation, written as the project earns it
data/          Synthea generation config and seeds; the generated bundles
               themselves are gitignored, they're reproducible, not stored
substrate/     the shared infrastructure every feature runs on
  synthea/       generates the synthetic patients, pinned Synthea version
  hapi-fhir/     the FHIR server, resettable to a known state between runs
  fhir-mcp/      the MCP server between agents and the FHIR server
features/      one folder per feature, agent + oracle + eval set
  f1_care_gap_hunter/
  f2_handoff_brief/
  f3_cohort_query/
  f4_prior_auth/
  f5_icu_triage/
experiments/   the three standing comparisons: tool granularity, scale,
               and FHIR serialisation strategy
harness/       shared code across features: trajectory logging, the eval
               runner, the base agent loop
notebooks/     scratch space, not a deliverable
```

`self-docs/` also exists in this repo but is gitignored. It's a personal
working notebook, not project documentation, so it isn't part of the layout
above.
